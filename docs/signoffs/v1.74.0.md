afterwards. This release is what it cost.

The reviewer's own attack was re-run against the new tests: the wrong
implementation that warned Mac users passed all 36 before and now fails.
Deleting the feature still fails only one test — but that one is an exact
string assertion, which is the correct shape for an existence check.

The composed sentence was reproduced through the real `storageRisk()`
before and after, not reasoned about:

    before: Safari deletes this app's data after a week away. Sign in
            first, or the installed app starts empty — on iPhone it gets
            separate storage, so trips saved here stay in Safari. …
    after:  Safari deletes this app's data after a week away. Sign in
            first — the installed app starts with its own storage. Then
            tap the Share button and Add to Home Screen.

## What was NOT verified

- **Still nothing on a real iPhone.** The owner's hardware test of the
  underlying claim — does an installed app actually start empty — was
  attempted and blocked by a separate UI bug (currency search rendering
  behind the keyboard). It is still outstanding, and the copy still rests
  on inference plus published sources rather than observation on the
  device.
- **The seven-day premise.** That WebKit's timer keeps running on the
  Safari copy after installing is inference from this codebase's own model.
  The reviewer fetched the WebKit storage-policy post the code cites and
  reports it does not state the home-screen exemption at all.
- **A real signed-in round trip** — sign in, install, confirm the fresh
  container re-syncs. Read from `syncNow()`, not observed.
- **This release was fixed by the same author the review was reviewing.**
  No second pass over these fixes.
