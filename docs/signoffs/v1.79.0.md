## What the verdict rests on, by instrument

- **The moved code is the same code** — the reviewer's *own* round-trip
  diff of the 326 removed lines against the new module. Every difference
  is one the boundary forces: an `export`, a `../` path, or a value that
  was a variable in `app.js` now read through a function so it stays
  live. Zero logic edits. This, not the suite, is what proves the claim.
- **The seam is wired** — the owner's Pixel 7 Pro ("1–5 works"): a wrong
  hook is a silent TypeError, and create-trip-with-a-member is the
  surface that dies first. Plus create/expense/delete driven in Chromium
  and real WebKit.
- **The deferral pair works** — both engines, through the *real* injected
  `sheetOpen`/`renderTrips` rather than stubs: a queued render does not
  repaint under an open sheet, and lands on its close.
- **The offline shell holds the new module** — live service-worker caches
  in both engines (50 entries, the new file among them), plus
  `tests/shell.test.mjs` walking the real import graph. **Never on a
  phone** — see below.

Tests are regression protection, not evidence. The reviewer ran its own
17 mutations rather than trusting either lane's: 13 killed, **4
survived**, and the survivors became TD-32/33/34. It also caught its own
first mutation harness reporting a false all-clear and reported that
rather than quietly re-running — a green mutation run being exactly the
instrument-outruns-itself shape.

## Comprehension gate

**In a user's words: nothing changes — not one pixel, not one tap.** What
moved is the machinery that keeps two phones in step: noticing a change
from your other phone, writing it down without bouncing it back, waiting
until you have finished typing before redrawing, and marking a trip
read-only rather than deleting it when this device cannot reach it. Every
visible thing behaves identically, and nothing about stored data changed
shape — `js/store.js` and `js/state.js` are both zero-line diffs.

## Lane attribution

Part A's adversary found six issues (README row, an invented comment
rationale, an async landmine for D-3, four orphan imports, two nits) and
**cried no wolf** — the QA lead confirmed every one independently. Its
core claim, "I could not break the extraction," survived an independent
attempt. Its one under-reach: its 16 mutations were confined to the new
module, while the two that mattered most live on the `js/app.js` side of
the seam — which is precisely where a seam breaks. The task lane found
pre-existing product friction (PB-31) and the landing-copy contradiction
(PB-30). The owner confirmed the wiring on hardware and E-1 with it.

Fixed in-sprint: the README module row, the four orphan imports (the
rulebook requires a change to remove the orphans it creates), and
ADR-0012's "~4s" claim against a `PUSH_DELAY_MS` of 1200.

## What was NOT verified

1. **No signed-in path ran, anywhere, by anyone — that is ~100% of what
   moved.** `absorbRemote`, `absorbInto`, `startLiveUpdates`,
   `applyLockout`, `noteAccess`, `readAccess`, `reportSyncFault` never
   executed. Evidence is byte-identity, unit tests and reading. TD-31,
   third sprint running.
2. **Six of the nine injected hooks never ran** — covered by a
   name-comparison test and by reading. A hook wired to the *wrong*
   function of the right name would pass every gate in this sprint.
3. **Offline boot has never happened on a phone.** Chrome refused the
   service worker over the gate link's self-signed certificate — caught
   by the E-3 probe *before* hand-over, so the owner was told to skip
   those steps rather than reporting a false failure.
4. **iPhone: nothing.** Still never tested on iOS.
5. Receipts, push, QR, two-device merge: untouched, not driven.

## Carried forward, unfixed, named so nobody thinks otherwise

**E-2** (two nested focus rings) escaped again — and was measured
properly for the first time: a 3px outline on the input *and* a 3px
box-shadow on the parent row. Sprint 7 measured the input, which is why
it read as fixed. It needs no hardware, so it belongs in a real
regression test rather than permanently in the escape corpus.
**E-3's app-side hardening** is still not done: id-minting has no
secure-context fallback, and the blast radius was measured this sprint as
worse than recorded — on an insecure origin a device holding older data
gets a *blank home screen at launch*, not merely dead taps.
