# v1.75.0 — release record

**A revert.** Cache `tripcash-v101`. 11 Aug 2026.

v1.73.0 and v1.74.0 are withdrawn. The iOS install warning is gone; the
plain instruction is back.

## Why

The warning asserted to users that installing to the home screen gives the
app storage separate from Safari's, so trips saved in Safari would not
appear in the installed app.

**That was never observed.** The evidence was:
- one indirect symptom on one phone — home currency read correctly in the
  installed app and wrongly in Safari, consistent with the installed app
  having no stored settings at all;
- published reports that iOS home-screen apps do not share storage with
  Safari;
- inference that trips and expenses live in the same container as settings.

The hardware test that would have settled it was attempted twice and
blocked both times by an unrelated bug: the currency picker's matches render
behind the iOS keyboard, so the trip could not be created.

A blind review of v1.73.0 separately found the shipped sentence
contradicting the warning it was composed into, and telling users their
trips "stay in Safari" — false on a seven-day timer. v1.74.0 fixed the
wording. It could not fix the fact that the claim was unverified.

## The decision

Owner's call: withdraw it. An iPhone user who installs and finds an empty
app gets a surprise. A user told something wrong about where their money
records are loses trust — and "telling somebody something false about their
data is worse than saying nothing" is this release's own reasoning, applied
to itself.

## Verified

| | |
|---|---|
| `npm test` | 815 pass, 0 fail |
| `npm run test:rules` | 57 pass, 0 fail |
| `npm run preflight` | clean |

The revert touched code and tests only. `CHANGELOG.md` and the sign-off
records for 1.73.0 and 1.74.0 were deliberately kept — the code is undone,
the history is not. Versions move **forward** to v1.75.0 / v101: devices
already cached v100, so reverting the version number would leave them on the
withdrawn build.

## What was NOT verified

- **Still nothing on a real iPhone**, which is the entire point of this
  revert.
- Whether the underlying claim is true. It remains in the product backlog
  with its reproduction and the blocked hardware test.
