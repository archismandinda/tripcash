# v1.73.0 — release record

**One fix: the iOS install warning.** Cache `tripcash-v99`. 11 Aug 2026.

> **Not independently reviewed.** Implemented and verified by the
> orchestrator, like v1.72.0. The tests are the only check and their author
> wrote the change.

## The change

On iOS a home-screen app gets storage separate from Safari's. A signed-out
person with trips who follows our own install prompt lands in an empty app.
`installAdvice()` now returns a different sentence for exactly that case:
iOS route, signed out, has data. Everyone else gets the plain instruction.

## Verified

| | |
|---|---|
| `npm test` | 819 pass, 0 fail |
| `npm run test:rules` | 57 pass, 0 fail |
| `npm run preflight` | clean |

Four tests, and the guard was disabled to confirm they fail without it
(35 pass / 1 fail). Covered: the warned case, the three unwarned cases
(no data, signed in, Android), already-installed, and prompt-holding
precedence.

## What was NOT verified

- **On a real iPhone.** The decision is pure and tested; the sentence has
  not been read on the device it is about. The owner's next hardware pass
  is the check that matters here.
- **That the two storage jars behave as believed for trips and expenses.**
  The owner observed it for *settings* — home currency differed between
  Safari and the installed app. Trips and expenses are almost certainly the
  same container, but that is inference, and this release's copy asserts it
  to users.
- No independent QA lane.
