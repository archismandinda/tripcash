# v1.77.0 — release record

**One change, decided by the owner: the shipped surface goes back to
v1.72.0.** Cache `tripcash-v103`. 12 Aug 2026.

> **This did not go through a sprint, a QA lane, or an independent review.**
> It is an owner-instructed revert, implemented and verified by the
> orchestrator alone, in the same session the instruction was given. Stated
> plainly rather than left to be inferred from the absence of a reviewer's
> name.

## The change

Four releases come out of the shipped surface: v1.73.0 and v1.74.0 (the iOS
install warning and its fixes), v1.75.0 (the withdrawal of that warning),
and v1.76.0 (sprint 7). Files reverted to `a55ac61`:

`index.html`, `styles.css`, `sw.js`, `js/app.js`, `js/desktop.js`,
`js/landing.js`, and `js/picker.js` deleted; with them the tests that
asserted the reverted behaviour (`picker`, `focus`, `fold`) and
`scripts/preflight.mjs`, whose check 9 measured a storefront that is no
longer here.

Kept, because they are not the shipped surface: every sign-off record for
v1.73.0–v1.76.0, every decision record, the timezone pin in `npm test`, and
the CSS, environment and browser-harness test infrastructure.

**The version number goes forward.** A device holding v1.76.0 must see a
service worker it considers newer, so this is v1.77.0 / cache v103, not a
return to v1.72.0 / v98. Settings will read **v1.77.0**; the app it labels
is v1.72.0's.

## The cost, which was on the table when it was decided

v1.76.0 was the release that fixed the currency search on an iPhone. It is
back: on a phone, typing to find a currency shows nothing, because the
search box sits under the keyboard and the scroller has no slack. That bug
stopped the owner twice and blocked two hardware tests, and its fix was
confirmed on an iPhone SE on 11 Aug (*"Yes, can see THB row, no problem"*).
The two-ring focus indicator returns, and the first screen returns to the
pre-storefront copy.

Going the other way, PB-28 is gone — verified below.

## Verified

| | |
|---|---|
| `npm test` | 829 pass, 0 fail, 0 skipped |
| `npm run preflight` | clean, all 8 checks |
| `npm run test:rules` | **not run** — `firestore.rules` is untouched by this revert |

Driven on the served tree in Chromium at 375×812, service workers and caches
cleared first:

- **It boots.** No console errors beyond the analytics beacon's CORS refusal,
  which is what a non-production origin always gets.
- **The About string reads v1.77.0**, which is how the revert will be
  confirmed on a phone.
- **The landing screen is v1.72.0's** — the pitch, the suitcase, "Start a
  trip". Screenshotted.
- **A trip can be created end to end**: name typed, `THB` searched, the match
  picked, saved. `tripcash:trips` holds one trip, `Bangkok Aug` / `["THB"]`,
  and the sheet closed.
- **PB-28 is not present.** With a query typed into the currency search, the
  trip name field and the member field are both still on screen
  (`offsetParent !== null` for each). That is the trap the revert was asked
  for, and it is gone.

## What was NOT verified

- **Nothing on hardware, and nothing under WebKit.** The WebKit binaries are
  on this machine but Playwright's driver is not installed, and ADR-0001
  forbids adding the dependency — so the one engine this revert is aimed at
  was not driven. **Mitigating, and the reason this was judged shippable:**
  this is not new code. v1.72.0 was live on 10–11 Aug and the owner used it
  on his iPhone in that window.
- **The clicks were synthetic.** The Browser pane stopped responding partway
  through, so the flow was driven by `.click()` from the console rather than
  by real pointer events. That proves wiring, not taps — and taps are exactly
  what the open blocker is about.
- **No independent review.** No second agent looked at the file set. The
  judgement that these eleven files are the whole shipped surface, and that
  the kept test infrastructure is feature-independent, rests on the suite
  going green and on nothing else.
- **The reverted bugs were not re-confirmed.** That the iPhone currency
  search is broken again is inferred from the code being identical to
  v1.72.0's, not observed.

## Correction to something said during the work

The Save button reading **"Create trip"** was attributed, in conversation, to
sprint 8a. It is not: v1.72.0 renders exactly that label once a currency is
picked on a new trip. The open blocker's button therefore predates 8a by
five releases, which widens rather than narrows what could be causing it.
